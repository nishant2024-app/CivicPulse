# Observability

## Signals

| Signal  | How                                                                                                    | Where to look        |
| ------- | ------------------------------------------------------------------------------------------------------ | -------------------- |
| Metrics | `prom-client`, prefix `civicpulse_`; `/metrics` on the API and on the workers (port 4100)              | Prometheus → Grafana |
| Traces  | OpenTelemetry spans created explicitly (HTTP, SQL, relay, Kafka, consumers, jobs) → Collector → Jaeger | Jaeger               |
| Logs    | Structured JSON (pino) with `trace_id`, secrets redacted                                               | Container logs       |

`/metrics` is not routed through the ingress.

## One trace across services

The trace context is stored on the outbox row, carried in Kafka headers, and copied into BullMQ
job payloads. A single report therefore produces one trace: HTTP request → SQL → outbox →
relay → Kafka → consumer → mail job. `scripts/jaeger-trace.py` fetches such a trace from Jaeger
and checks its shape; `apps/api/test/tracing.test.ts` covers propagation.

Tracers are obtained per call, never at module load: a tracer taken before the provider exists
yields non-recording spans (this was a real bug here).

## Dashboards

Six Grafana dashboards are generated by `scripts/gen-dashboards.py` and provisioned from Git:
API performance, Application health, Background processing, Database performance, Error monitoring and Event streaming. CI fails if the generated
files differ from the committed ones. `scripts/check-dashboards.py` runs every dashboard query
against Prometheus: in the last cluster run 49 queries were valid, 39 returned data and 10
returned nothing yet (for example error counters that had no errors).

## Failure drills

`scripts/drills.py` breaks one dependency at a time and checks the product's promise. All five
passed on Docker Compose and in the Kubernetes cluster run.

| Dependency down | What must still be true                                              |
| --------------- | -------------------------------------------------------------------- |
| Workers         | Reports are still saved; events wait in the outbox, then drain       |
| Redis           | API keeps serving; cache and rate limit fail open                    |
| OpenSearch      | Search falls back to PostgreSQL; indexing is repaired by redrive     |
| Kafka           | Reports are still saved; the outbox holds events until Kafka returns |
| Mail provider   | Notification emails are retried and delivered after recovery         |

Run them: `python3 scripts/drills.py docker` (Compose) or `python3 scripts/drills.py kube`.
